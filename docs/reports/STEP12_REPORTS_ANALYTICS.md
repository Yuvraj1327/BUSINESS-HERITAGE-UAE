# STEP 12 — Reports, Analytics, Data Export and Activity History

Owner only. Nothing in this step changes a financial rule: every figure is read from the same records and the
same functions as Steps 7–11 and is only grouped, filtered, charted or exported here.

## 1. Design in one paragraph
Every report is built **once** as a `Table` (columns, rows, summary totals, notes) in
`backend/app/services/analytics_service.py`. The screen, the CSV file, the Excel file and the charts all consume that
same table, so an exported total can never differ from the total on screen, and paging or sorting on screen never
changes an export (exports always contain every row of the filter, capped at 100,000). There is no second copy of any
formula: calculations come from `core/calculations.py`, balances from `public.app_cash_bank_ledger()`, supplier balances
from `v_supplier_outstanding`, task rules from the Step 11 service, and so on.

## 3. Calculation definitions
| Figure | Definition (single source) |
|---|---|
| Total sales / orders | sum over non-voided `daily_reports` in the range (`reports.totals`) |
| Total collections | cash + POS + bank transfer + payment link (`calc.total_received`) |
| Difference / not yet received | `sales − collections` / `max(difference, 0)` (`calc.difference`, `calc.not_yet_received`); status text `Matches` / `Diff` (`calc.check_label`) |
| Shop expenses | shop expenses **excluding** shop savings (`calc.shop_expenses_excl_savings`); savings are shown separately |
| Head office expenses | head office expenses **excluding** rows marked as Saving (`calc.head_office_excl_savings`) |
| Total savings | shop savings + head office savings in the range (`calc.total_savings`); *savings position* additionally includes savings brought forward from the opening balances |
| Sales minus expenses | `sales − (shop excl. savings + head office excl. savings)` (`calc.sales_minus_expenses`) |
| Cash + bank balance | company-wide closing position at the end date from `app_balances` (not branch-filtered; the report notes say so) |
| Account opening / closing | opening balance plus every ledger movement up to the day before / the end date; each transaction exists once in the ledger |
| Supplier outstanding | opening dues + dues − payments (`v_supplier_outstanding`); voided entries excluded |
| Cleared cheques | counted **only** when `cleared_on` is in the range; Pending and Bounced cheques are never added to cleared totals or to any balance |
| Overdue task / missing report | Step 11 rules (due before today and not Done; Step 7 missing-report definition) |

## 4. Exports
`GET /reports/{key}/export?format=csv|xlsx` and `GET /reports/activity/export`. Generated by the backend
(`export_service.py`, `openpyxl` write-only mode for Excel). Each file starts with the report name, company, generated
time (Dubai), date range, grouping, branch and currency, then the **summary totals**, then the table, then notes.
Money is written with two decimals (CSV) or as numbers with an AED number format (Excel). Cells that start with
`= + - @` are prefixed with `'` (spreadsheet formula-injection guard). Responses are `Cache-Control: no-store`.
Branch Users get 403 (they have no `REPORTS.EXPORT` or `AUDIT_LOG` grant); there is no frontend-generated export, so
there is no URL that could return restricted rows.

## 5. API
All routes are under `/api/v1/reports`, require a signed-in Owner (`REPORTS.READ`, exports `REPORTS.EXPORT`, activity
`AUDIT_LOG.READ`), and return 403 (plus an `ACCESS_DENIED` audit row) for anyone else, 401 when anonymous.

| Route | Purpose |
|---|---|
| `GET /catalog` | list of reports (key, category, title, description) |
| `GET /overview` | the eight KPI cards |
| `GET /charts` | the eleven charts |
| `GET /{key}` | one report: `sort`, `desc`, `page`, `page_size` (≤ 200) |
| `GET /{key}/export` | CSV or Excel, all rows |
| `GET /activity`, `/activity/export`, `/activity/actors` | activity history |

Shared filters: `date_from`, `date_to` (default: first of the month to today; max 366 days; never in the future;
Dubai dates), `period` (`day|week|month|year`), `branch_id` (must exist), `supplier_id`, `account`
(`Cash|ENBD|ADCB|POS Pending`), `kind` (ledger: `transfers|pos_settlements|rental_cheques|daily_reports|expenses`).
Invalid filters return 422 with field messages; an unknown report key returns 404.

Performance: each request memoises its source queries, groups in SQL, and pages in Python for the table reports (the
activity history pages in SQL). Migration `0016_report_indexes.sql` adds partial/date indexes for the new range scans.

## 6. Activity History
Reads the **existing** `audit_log` (append-only; not modified, no second audit system). Columns: date/time (Dubai),
user, action (Created / Updated / Deleted / Access denied), module, record, change summary, reason. Filters: user,
module, action, date range, record id / reason text. Keys containing `password`, `token`, `secret`, `api_key`,
`service_role` and bookkeeping columns are removed from change summaries.

## 7. Frontend
`/reports` (Reports & Analytics) and `/activity-history`, both Owner-only and lazy-loaded. Quick ranges (Today,
Yesterday, Last 7/30 Days, This/Last Month, This Year, Custom), grouping, branch, eight KPI cards, category tabs, sortable
paginated table, totals strip, Charts tab (recharts, AED tooltips, empty states), CSV / Excel buttons with progress and
error toast. Axios + TanStack Query; no service-role key anywhere in the frontend.

## 8. Known limitations and unresolved decisions (numbered X1…)
- **X1** Export downloads are logged to the application log (`app.audit` logger) but are **not** rows in `audit_log`:
  the audit table only accepts its approved actions and Step 12 must not alter it. Owner to decide if exports must be audited.
- **X2** The Cash + Bank KPI and the cash reports are company-wide; a branch filter narrows branch cash only.
- **X3** Activity search matches the record id and the reason, not record titles (searching inside raw values could
  expose masked fields).
- **X4** Report and export size limits: 366 days per request, 100,000 rows per export.
- **X5** Alerts still have no scheduler (see Step 11 T9); the reports read current data.
- **X6** Reports are not saved or scheduled; there is no PDF output.
- **X7** Report columns are fixed; there is no column picker.
